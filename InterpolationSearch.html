Interpolation Search

Binary search always checks the middle. Interpolation search makes an educated guess — like flipping straight to "M" in a phone book instead of opening to the center. This page runs the real algorithm in your browser: try it, race it against binary search, and benchmark both.

02 · How the probe is placed

It's just a proportion

Think of the sorted array as a ruler. If you're searching for 87 in a range that runs from 0 to 100, you don't start in the middle — you start about 87% of the way along. That's the entire idea. Binary search ignores the values and always halves; interpolation search looks at the values and jumps proportionally.

Start with the same bounds as binary search

lo is the first index, hi is the last index — exactly like binary search.

Estimate a position instead of halving

Where binary search always computes mid = (lo + hi) / 2, interpolation search asks "how far is my target between arr[lo] and arr[hi], proportionally?" and places pos there:

pos = lo + ⌊ (target − arr[lo]) × (hi − lo) / (arr[hi] − arr[lo]) ⌋

The fraction (target − arr[lo]) / (arr[hi] − arr[lo]) is "how far across the value range the target sits" — 0 means it equals arr[lo], 1 means it equals arr[hi]. Multiplying that fraction by the index range (hi − lo) converts a value-position into an index-position.

Compare and shrink the range

Same three outcomes as binary search: if arr[pos] equals the target, done. If it's smaller, move lo to pos + 1. If it's larger, move hi to pos − 1. Repeat.

Why "uniform data" matters so much

The formula assumes values are spread out roughly evenly between arr[lo] and arr[hi]. When that's true, each guess lands close to the real answer and the search finishes in roughly O(log log n) steps. When the data is bunched up unevenly (say, a huge outlier at one end), the proportion the formula computes stops meaning much, and performance can fall all the way to O(n) — a straight scan. 05 · Complexity at a glance

When to reach for which

AlgorithmBest caseAverage case (uniform data)Worst caseRequires
Binary search O(1) O(log n) O(log n) Sorted array
Interpolation search O(1) O(log log n) O(n) Sorted & roughly uniform array

The headline number people quote — O(log log n) — only holds when the data is roughly uniformly distributed. It's a bet on the shape of the data, not just its order. That's the whole trade-off in one sentence.
