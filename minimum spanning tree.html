01 — Problem statement

What is a Minimum Spanning Tree?

Given a connected, undirected, weighted graph G = (V, E), a spanning tree is a subgraph that connects all V vertices using exactly V − 1 edges and contains no cycles. A minimum spanning tree is the spanning tree whose total edge weight is as small as possible.

MSTs matter anywhere you need to connect a set of points as cheaply as possible: laying network cable between offices, routing utility lines between towns, clustering data points, or approximating harder problems like the Travelling Salesman Problem. Both algorithms below produce a guaranteed-optimal MST — they differ only in how they grow it.

Kruskal — edge-centric

  • Sorts all edges globally by weight first
  • Greedily adds the cheapest edge that doesn't form a cycle
  • Cycle check via a Union–Find (disjoint-set) structure
  • Builds a forest that merges into one tree

Prim — vertex-centric

  • Grows one tree outward from a start vertex
  • At each step, adds the cheapest edge leaving the current tree
  • Tracks the "frontier" via a min-priority queue
  • Always maintains a single connected component
02 — Algorithm

Kruskal's Algorithm

Sort every edge by weight, then walk the sorted list once: accept an edge if its two endpoints sit in different components, and merge those components. Reject it if they're already connected — adding it would create a cycle. This is a direct application of the cut property: the lightest edge crossing any cut of the graph is safe to include in some MST.

10function Kruskal(V, E):
    MST ← ∅
    sort E by weight ascending
    DSU ← MakeSet(V)               // each vertex its own set
    for (u, v, w) in E:
        if DSU.Find(u) ≠ DSU.Find(v):
            MST.add((u, v, w))
            DSU.Union(u, v)
    return MST                    // |MST| = |V| − 1

20class UnionFind {
  constructor(n) { this.p = [...Array(n).keys()]; this.rank = Array(n).fill(0); }
  find(x) { while (this.p[x] !== x) { this.p[x] = this.p[this.p[x]]; x = this.p[x]; } return x; }
  union(a, b) {
    let ra = this.find(a), rb = this.find(b);
    if (ra === rb) return false;
    if (this.rank[ra] < this.rank[rb]) [ra, rb] = [rb, ra];
    this.p[rb] = ra;
    if (this.rank[ra] === this.rank[rb]) this.rank[ra]++;
    return true;
  }
}
function kruskal(n, edges) {
  const sorted = [...edges].sort((a, b) => a.w - b.w);
  const dsu = new UnionFind(n);
  const mst = [];
  for (const e of sorted)
    if (dsu.union(e.u, e.v)) mst.push(e);
  return mst;
}
02 — Algorithm

Prim's Algorithm

Start at any vertex and mark it visited. At every step, look at all edges with exactly one endpoint inside the growing tree — the frontier — and add the cheapest one, pulling a new vertex in. Repeat until every vertex is visited. This also follows the cut property, applied at the single cut between "visited" and "unvisited" vertices.

11function Prim(V, E, start):
    visited ← {start}
    MST ← ∅
    heap ← min-heap of edges leaving start, keyed by weight
    while |visited| < |V|:
        (u, v, w) ← heap.popMin()      // cheapest frontier edge
        if v in visited: continue       // stale entry, skip
        MST.add((u, v, w))
        visited.add(v)
        for each edge (v, x, w2) where x ∉ visited:
            heap.push((v, x, w2))
    return MST

17function prim(n, adj, start = 0) {
  const visited = Array(n).fill(false);
  visited[start] = true;
  const mst = []; let visitedCount = 1;
  while (visitedCount < n) {
    let best = null;
    for (const e of adj)                    // swap for a real heap at scale
      if (visited[e.u] !== visited[e.v])
        if (!best || e.w < best.w) best = e;
    if (!best) break;                       // graph disconnected
    mst.push(best);
    visited[visited[best.u] ? best.v : best.u] = true;
    visitedCount++;
  }
  return mst;
}

04 — Comparative analysis

Kruskal vs. Prim, side by side

AspectKruskal'sPrim's
ApproachEdge-centric, global sortVertex-centric, local frontier
Core structureUnion–Find (disjoint set)Min-priority queue / heap
Time (heap/DSU)O(E log E)O(E log V) with binary heap
Time (dense, array)O(E log E) — sort dominatesO(V²) with simple array — often faster
SpaceO(V + E)O(V + E)
Best suited forSparse graphs, edge-list inputDense graphs, adjacency-matrix input
Intermediate stateA forest (multiple components)Always one connected tree
Cycle avoidanceExplicit Find/Union checkImplicit — only unvisited vertices join
ParallelizableSorting step parallelizes wellHarder — inherently sequential growth

In practice: pick Kruskal when the graph is sparse and already available as an edge list, or when you need an easy way to stop early with a bound. Pick Prim when the graph is dense, stored as an adjacency matrix, or when a Fibonacci heap is available, since it then achieves O(E + V log V).
