string matching field notes

Three ways to find a needle in a haystack of text.

Naive scanning, Rabin–Karp hashing, and Knuth–Morris–Pratt's failure function all solve the same problem — they just refuse to waste the same amount of work doing it. This is a side-by-side dissection of how, and how much that difference costs.

the contenders

Same job, three different instincts.

Brute force

Naive Search

Try every alignment. At each one, compare characters left to right until a mismatch, then slide the pattern one step and try again. No memory of what was already learned.

Worst caseO(n·m)
SpaceO(1)

Fingerprinting

Rabin–Karp

Hash the pattern once, then slide a rolling hash across the text in O(1) per step. Only fall back to a real character check when two hashes happen to collide.

Worst caseO(n·m)
AverageO(n+m)

Self-aware

Knuth–Morris–Pratt

Pre-analyze the pattern for its own repeated prefixes (the "failure function"), so after a mismatch it never re-examines a text character it already matched.

Worst caseO(n+m)
SpaceO(m)

the implementations

Read the logic, not just the Big-O.

function naiveSearch(text, pattern) {
  const n = text.length, m = pattern.length;
  const matches = [];

  for (let s = 0; s <= n - m; s++) {      // every possible alignment
    let j = 0;
    while (j < m && text[s + j] === pattern[j]) {
      j++;
    }
    if (j === m) matches.push(s);       // full pattern matched
  }
  return matches;
}
function rabinKarp(text, pattern) {
  const n = text.length, m = pattern.length;
  const d = 256, q = 101;      // base and a prime modulus
  const matches = [];
  let h = 1;
  for (let i = 0; i < m - 1; i++) h = (h * d) % q;

  let patHash = 0, textHash = 0;
  for (let i = 0; i < m; i++) {
    patHash  = (d * patHash  + pattern.charCodeAt(i)) % q;
    textHash = (d * textHash + text.charCodeAt(i))    % q;
  }

  for (let s = 0; s <= n - m; s++) {
    if (patHash === textHash) {          // cheap filter
      if (text.slice(s, s + m) === pattern) matches.push(s);
    }
    if (s < n - m) {                   // roll the hash forward, O(1)
      textHash = (d * (textHash - text.charCodeAt(s) * h)
                    + text.charCodeAt(s + m)) % q;
      if (textHash < 0) textHash += q;
    }
  }
  return matches;
}
function computeLPS(pattern) {
  const m = pattern.length;
  const lps = new Array(m).fill(0);
  let len = 0, i = 1;
  while (i < m) {
    if (pattern[i] === pattern[len]) { lps[i++] = ++len; }
    else if (len !== 0) { len = lps[len - 1]; }   // fall back, don't retreat i
    else { lps[i++] = 0; }
  }
  return lps;
}

function kmpSearch(text, pattern) {
  const n = text.length, m = pattern.length;
  const lps = computeLPS(pattern);
  const matches = [];
  let i = 0, j = 0;

  while (i < n) {
    if (text[i] === pattern[j]) { i++; j++; }
    if (j === m) { matches.push(i - j); j = lps[j - 1]; }
    else if (i < n && text[i] !== pattern[j]) {
      j !== 0 ? j = lps[j - 1] : i++;   // text pointer i never rewinds
    }
  }
  return matches;
}

the verdict

So which one should you reach for?

Reach for Naive when…

The text is short, the code needs to be obviously correct, or this runs once. Its simplicity is the whole feature — no preprocessing, nothing to get wrong.

Reach for Rabin–Karp when…

You're searching for many patterns at once, or matching whole substrings/documents, where comparing hashes is far cheaper than comparing raw text (plagiarism and duplicate-content detection lean on this).

Reach for KMP when…

Worst-case guarantees matter — streaming data, adversarial input, or a single long-lived pattern searched repeatedly, where linear time can't be negotiated away.
